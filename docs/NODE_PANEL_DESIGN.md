# Evidence-First Node Research Workspace — UI/UX design system V3

## 产品定位
每个节点是可审计的研究对象：**实体身份—技术内容—数量口径—企业关系—证据—未解决问题**。前端不应简单把JSON渲染成代码块；整个网站的目标是让分析师在一个页面完成发现、核对、比较和反向追踪。

### 六标签信息架构
1. **总览**：标题、实体ID、节点层级、研究状态和显著的“技术关联≠采购”风险提示；最重要的2—4条事实卡片。
2. **技术与原料**：独立SKU物性表（值、单位、条件、来源、版本）、配方类别、上游工业原料及替代工艺。无数据必须展示“未核实”。
3. **市场与企业**：只有附地区/年限/统计指标/分母的TOP3才可显示百分比条形图；部门营收、产能、国家矿产量以其他指标呈现。企业能力、采购关系和市场占比三个概念分开。
4. **上下游**：选择节点后向上游展开和向下游导航；边标签明确 `associated_with`、`material_input`、`uses_equipment`；跨产品反向查询不把相关企业误作实际客户。
5. **原始证据**：每条原子论断显示证据状态、来源ID、来源发布时间和原文链接；同集团多页面标记非独立信源。
6. **风险与待办**：研究缺口、反证、牌号认证问题、供应集中风险；任务优先级为研究计划，并非客观市场评级。

### 交互与屏幕适配
- 桌面：图谱(约63%) + 可独立滚动的研究面板(约37%，最大620px)；顶部产品导航和操作区不覆盖画布。
- 小屏：上下分区，图谱高度约66vh、详情在下方；标签可水平滚动。
- 图谱支持缩放、拖动、折叠、展开、键盘节点导航；标签按钮采用 `role=tab` 和 `aria-selected`。
- 单个事实最多一屏展示精度要点，长表格使用字段网格/分栏，源网址另行列出；避免 raw JSON。
- 跨节点切换默认返回“总览”；公司详情有“返回节点”的动作。

### 证据显示规则
| 事实 | 可读标签 | 错误做法 |
|---|---|---|
| LOCTITE 243 粘度 | 1300–3000mPa·s · 25°C / Brookfield / 2025版TDS | “243粘度=3000，已证实” |
| TECHNOMELT EVA 应用温度 | 130–150°C · 2022版TDS | 作为所有热熔胶通用温度 |
| Henkel业务2025收入 | 10,667百万欧元 · FY2025 / 全业务部门 | 当作胶黏剂全球市占率 |
| 胶黏剂供应商TOP3缺失 | 暂无同口径可核实数据 | 擅自列出科思创、万华等比例 |

### 当前实现边界
- 结构化页面 `web/assets/node_panel.js`：6标签、状态、数据卡片、市场口径、证据来源、反向查询。
- `scripts/validate_intelligence.py`：节点资料和来源结构校验，**不进行语义真假判断**。
- 尚未实现离线全文证据缓存、专业图谱聚类自动布局、市场数据源实时同步和浏览器端全流程人工验收。
- 数据视图将业务品牌、物理配方和终端应用保持分离；复杂火箭也必须类似分开构型和工程系统。

## 验收流程

```bash
python scripts/validate_intelligence.py data/products/henkel-adhesives/graph.json
python -m unittest discover -s tests -v
node --check web/assets/node_panel.js
node --check web/assets/app.js
python scripts/build_site.py
```
